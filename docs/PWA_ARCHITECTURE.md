# PWA Architecture

LunaFlow is a Progressive Web App (PWA) using `vite-plugin-pwa` with Workbox `generateSW` mode. The service worker caches the app shell for offline access, while all user data is stored locally in IndexedDB with optional Google Drive sync.

## Service Worker Strategy

### Registration

- **Mode**: `autoUpdate` — new service worker versions activate immediately without user interaction
- **Generation**: `generateSW` — Workbox auto-generates the service worker; no custom SW code
- **Scope**: `/` (root)
- **Dev mode**: Disabled (`devOptions.enabled: false`) to avoid caching issues during development

### Precaching

All build output assets are precached on first load:
- JavaScript bundles, CSS, HTML
- Icons (PNG, SVG), fonts (WOFF2)
- Pattern: `**/*.{js,css,html,ico,png,svg,woff2}`

### SPA Navigation

- `navigateFallback: 'index.html'` — all navigation requests serve the cached SPA shell
- `navigateFallbackDenylist: [/^\/api\//]` — API routes (Vercel serverless functions) are excluded from the fallback

### Runtime Caching Rules

| Pattern | Strategy | Rationale |
|---------|----------|-----------|
| Build assets | Precache | App shell must load offline |
| `/api/auth/*` | Excluded via denylist | Auth tokens must never be cached; routes must reach Vercel serverless functions |
| `www.googleapis.com/*` | NetworkOnly | Data sync uses IndexedDB as offline source; caching would cause stale data |
| `accounts.google.com/*` | NetworkOnly | Google Identity Services SDK, non-cacheable |
| `apis.google.com/*` | NetworkOnly | GAPI SDK, non-cacheable |
| `www.googletagmanager.com/*` | NetworkOnly | Analytics, non-cacheable |

## Offline Behavior

### What works offline

- **App shell**: Fully cached — the entire UI loads from service worker cache
- **Calendar data**: Available from IndexedDB — all events, stats, predictions work offline
- **Navigation**: SPA routing works offline via `navigateFallback`

### What does not work offline

- **Google Drive sync**: Skipped when offline (`syncState.status === 'offline'`)
- **Google OAuth login**: Requires network (Google SDK scripts won't load)
- **Analytics**: GTM calls silently fail

### Offline detection

- `useRemoteSync` monitors `navigator.onLine` and `online`/`offline` window events
- When offline: sync operations are skipped, `syncState.status` is set to `'offline'`
- Header displays a `WifiOff` icon in amber when offline
- When connectivity returns: `performFullSync` triggers automatically (if authenticated), performing a full bidirectional merge

### No sync queue needed

The existing architecture handles offline gracefully without a separate queue:
1. All changes save to IndexedDB immediately (via `useCalendarEvents`)
2. On reconnect, `performFullSync` does a full bidirectional merge using Last-Write-Wins
3. This effectively "retries" any missed syncs without dedicated queue infrastructure

## Install Experience

### Manifest

The manifest is generated by `vite-plugin-pwa` from the config in `vite.config.ts`. Key fields:
- `display: 'standalone'` — app runs without browser chrome
- `start_url: '/'` — SmartRedirect routes returning users to `/calendar`
- `categories: ['health', 'lifestyle', 'medical']`
- `shortcuts` — "Open Calendar" shortcut to `/calendar`

### Icons

- SVG favicon (any size)
- 192x192 PNG (standard)
- 512x512 PNG (splash screen + maskable)

### How to install

- **Chrome/Android**: Browser automatically shows install prompt (mini-infobar)
- **Safari/iOS**: Share button > "Add to Home Screen"
- **Firefox Android**: Menu > "Install"

## Vercel Deployment

### Service worker headers

`vercel.json` sets `Cache-Control: public, max-age=0, must-revalidate` on `/sw.js` to ensure browsers always check for updates.

### Static file serving

Vercel serves static files (including `sw.js`, `workbox-*.js`) before applying rewrite rules, so the SPA fallback rewrite does not interfere with service worker requests.

### API route protection

`navigateFallbackDenylist: [/^\/api\//]` prevents the service worker from intercepting `/api/auth/*` routes, which must reach Vercel serverless functions for OAuth to work.

## Cross-Browser Compatibility

### Chrome / Android
Full PWA support: service worker, install prompt, all Workbox caching strategies, offline mode.

### Firefox
Service worker and offline caching work correctly. PWA installation is supported on Android but **not on desktop** (removed in 2021). This aligns with the design: PWA for mobile, web app for desktop.

### Safari / iOS
- **Service workers**: Supported. Cache may be evicted after 7 days of inactivity for sites NOT added to home screen; for installed PWAs (added to home screen) this restriction is relaxed.
- **Manifest**: Safari relies more on `apple-mobile-web-app-*` meta tags than `manifest.json`. All required meta tags are in `index.html`: `apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style`, `apple-mobile-web-app-title`, `apple-touch-icon`.
- **Install**: No `beforeinstallprompt` event — users install via Share > "Add to Home Screen".
- **Background Sync API**: Not supported on iOS. The app uses the `online` window event instead, which works everywhere.

### navigator.onLine
Can report false positives across all browsers (device connected to LAN but no internet). Sync errors are caught by the existing try-catch error handling as a fallback.

## Manual Testing Checklist

1. Build and preview: `npm run build && npm run preview`
2. Chrome DevTools > Application: verify SW registered, manifest valid, cache populated
3. DevTools > Network > check "Offline": reload — app loads, data visible, WifiOff icon shown
4. Uncheck "Offline": sync triggers automatically if authenticated
5. Lighthouse > PWA audit: all checks pass
6. Mobile: install via browser prompt (Chrome) or Share > Add to Home Screen (Safari)

## LLM Development Rules

- **NEVER** add caching for `/api/auth/*` routes — these must remain excluded via `navigateFallbackDenylist`
- **NEVER** cache Google Drive API responses — IndexedDB is the single source of offline truth
- **NEVER** use the Background Sync API — not supported on iOS Safari
- When adding new API routes, add them to `navigateFallbackDenylist` in `vite.config.ts`
- When adding new external script dependencies, add `NetworkOnly` runtime caching rules
- Preserve all `apple-mobile-web-app-*` meta tags in `index.html` — Safari depends on them
- Test PWA across Chrome, Firefox, and Safari
- Test PWA behavior via `npm run build && npm run preview` — the dev server does NOT enable service workers
- Verify service worker in Chrome DevTools > Application > Service Workers
- The service worker is auto-generated by Workbox — do NOT write custom service worker code unless migrating to `injectManifest` mode
